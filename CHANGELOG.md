# Changelog

All notable changes to Footfall are recorded here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and Footfall uses [semantic versioning](https://semver.org/).

## [Unreleased]

- `footfall test <folder>` runs the AI testers against a local folder. It copies only the files git tracks, so a `.env` kept out of git never reaches a container, whatever the tested branch's own `.gitignore` says, and it refuses a sparse checkout, or any checkout where git skips a file in the working tree, since there a branch can track the name of a file of yours that git then leaves in place; test a full checkout, or pass `--all-files`. For the same reason it refuses a tracked file changed in the checkout, or marked assume-unchanged, that your own git excludes name, `.git/info/exclude` and `core.excludesFile` or git's default global excludes but never the tree's `.gitignore`, and names it, to be removed or renamed. `--untracked` adds the untracked files git does not ignore, which that `.gitignore` decides, and names each on standard error before the copy. A folder outside git needs `--all-files`, which warns that it copies everything, and the two flags cannot be used together. It never reads or writes through a link, and it never copies the repository's own git folder or a linked worktree's common folder, however a crafted index or a `.git` file names them. It refuses a submodule, whose files git does not list, and with `--untracked` a nested repository too, and it leaves out untracked files in any folder shaped like a git folder, such as a nested repository's. With `--all-files` it leaves out every `.git`, every folder git names as a git folder, and every folder shaped like one, with a `HEAD` file and an `objects` folder, or a `commondir` file. git runs with none of Footfall's environment, no input and no way to fetch, and reads a repository someone else owns only where the system trusts it; the footfall image trusts `/repo`, where the dev stack mounts the repository under test. It asks the runner to prepare the app, start a copy for each persona and start the run's browsers, signs each persona in when the brief asks, then writes each persona's report, step trace and screenshots, a summary of the run and a table of the results. The run is stopped however it ends, and the throwaway password reaches only the seed step.
- A `footfall test` run has a cost ceiling the operator sets and the tested repository cannot raise: `--cost-ceiling`, or `FOOTFALL_RUN_COST_CEILING_USD`, in dollars, $12 unless set, the design's worst case for the default personas. Each persona checks the run's spend before each turn, and once it reaches the ceiling no persona starts another, so a run can pass it by at most one turn for each persona running. A value that is not a number of dollars from 0.01 to 1000 is a setting error.
- A persona stopped at its hard limit reports what its model calls cost until then, so `summary.json` no longer reads low when a run goes wrong.
- `footfall runner` serves the runner, the one process that holds the Docker socket, on a Unix socket that only its own group can use.
- `footfall proxy` serves the egress proxy and its control socket.
- `FOOTFALL_DISK_BUDGET_MIB` sets how much disk the runner lets one run use, counting every copy of its app. It is 8192 MiB unless set, and a value that is not a whole number from 1 to 16,777,216 (16 TiB), an empty one included, stops the runner with an error.
- Each run's browser container puts a gate in front of Playwright's server, which listens on loopback alone. The gate passes on only a WebSocket upgrade for a path made fresh for that run, which only the orchestrator is told, and answers every other request with an empty 404, so code under test can neither learn the path nor launch a browser of its own there. Each connection has 10 seconds to send its request, and connections held open from one address cannot crowd out the orchestrator's. When the container stops, the gate stops run-server and everything it started within a few seconds, and if the gate goes, run-server goes with it.
- The browser image installs a Chromium managed policy that turns off Encrypted Client Hello, which the egress proxy refuses, and the run's Chromium starts as the full build, since the headless shell reads no policies.
- Every container the runner starts has an init process, and the browser container has 512 MiB of shared memory for Chromium.
- The host has no address on a run's network, so code under test cannot reach what the host serves, and every container the runner starts finds the egress proxy by name in its hosts file, since Docker's name service does not answer under gVisor.
- `deploy/dev/compose.yaml` runs the proxy, the runner and an orchestrator for development. Each is read-only, runs under an init process and has no capabilities beyond what it needs, only the runner mounts the Docker socket, and only the orchestrator receives the Anthropic key. The orchestrator mounts the repository under test read-only with its `.git`, and the footfall image carries git, so the copy is git's there too. With `FOOTFALL_RUNTIME=runc`, for a machine without gVisor, every command warns that containers start without it.
- The isolation workflow, `.github/workflows/isolation.yml`, builds the images, installs gVisor and starts the dev stack, then runs the sandbox's own tests in its orchestrator: what an app container can be, hold and reach, the egress proxy's decisions, the browser container's gate, and a whole `footfall test` run of the demo app. It records the peak memory of each kind of container in the job summary.
- Tiny Tasks, the demo app in `demo-app/`: a to-do list with twelve planted usability and accessibility bugs, listed in its `BUGS.md`, with a manifest and a brief for Footfall to test it.
- `footfall.toml` and the briefs are read strictly, with every problem reported at once. A path on the app may not hold a control or invisible character, a `#`, or a `.` or `..` segment, however it is spelt. Each list holds at most 64 entries, a host listed twice is a problem, and a byte order mark at the start of a file is ignored.
- The egress proxy refuses the deprecated 6to4 relay anycast range 192.88.99.0/24, the Port Control Protocol anycast addresses 192.0.0.9 and 2001:1::1, the TURN anycast addresses 192.0.0.10 and 2001:1::2, and ORCHIDv2's 2001:20::/28, which no public host uses, and a host name whose last label is a number in any base is taken for an address and refused.
- A persona's `locale` must be a language tag such as `en-GB`, and its `timezone` one the system's time zone database knows, so a typo stops the personas file from loading.
- Every container the runner starts has a private IPC namespace and a core file limit of 0, and its settings say that `/tmp` runs no programs, which Docker already ensured. The runner walks an app's files without ever opening a folder through a link, stops a run whose files keep vanishing or changing under three disk measures in a row, each taken twice when the first skips something, and says to keep scratch files in `/tmp`, and remembers the latest 10,000 run ids it has stopped.
- Text a tester writes loses the characters that show nothing, such as zero-width spaces, word joiners and the byte order mark, as well as the bidirectional controls, and the line and paragraph separators become plain new lines.
- `footfall test` refuses a file that is, by a hard link under another name, the repository's git configuration or any other file of its git folder, such as a submodule's configuration, or, for a submodule, of each superproject's out to the outermost, and refuses such a file if it cannot read or find all of them, and warns once for each folder it leaves out because it is shaped like a git folder, a `HEAD` that is a link included.
- In a GitHub Actions job, Footfall registers each secret it makes, a run's throwaway password and the path of its browser server, with `::add-mask::`, so the job's log shows `***` in its place. The command goes only to a pipe or a terminal, never to a file an artefact could hold or to /dev/null, and if no stream a job reads takes it, the run stops before the secret is used.
- The isolation workflow's `memory.json` says what every kernel peak covers, the run or the stack's whole life, its total included.
- The runner keeps each run's files in `/var/lib/footfall-runs` (`FOOTFALL_RUNS`), which must belong to root and be writable by root alone, or the runner will not start; it checks the folders above it as its own container shows them, so on the host each folder above it must be root's alone too, as on a stock Ubuntu. Only the runner mounts it, and the orchestrator no longer can. Make it with `sudo install -d -o root -g root -m 0700 /var/lib/footfall-runs`. The runner writes, gives away, sets the modes of and removes everything there through folders it holds open, never through a link, and opens a folder's path again before it names it to Docker.
- A run's folder is removed by a walk that holds a few open folders at a time, however deep the tree its code made, rather than one for each level.
- Before it serves, the runner removes every container, network and run folder that an earlier runner left, saying what it removed. It stops any run that lasts longer than `FOOTFALL_RUN_LIFETIME_MINUTES`, 90 unless set, and a value that is not a whole number from 1 to 10080 stops it from starting. A hang-up stops `footfall test`, and its run, as SIGTERM does.
- The egress proxy listens only at its own address on each run's network, from when the runner tells it until the run stops, rather than on every interface, and its control socket answers root alone, checked by the connecting process's user id.
- The proxy looks up each run's names on that run's own threads, with at most 8 lookups in flight for each client and 16 for each run, so one run's slow name server cannot delay another's; past those it answers 503. Those threads go once the run holds neither an allow list nor a listener, a run it no longer serves gets none, and before it serves, the runner revokes in the proxy every run that nothing else shows is still there.
- The proxy refuses the AS112 and AMT anycast ranges. For plain HTTP it drops `Forwarded`, `X-Forwarded-Host` and the other headers that name another host, and it refuses header values holding the bytes 0x80 to 0x9F. Revoking an allow list closes that address's open connections.
- The proxy writes each client's refusals for a run in full up to a budget a minute, 20 for routine refusals (its connection and lookup limits, hosts off the list) and a separate 100 for all others, such as TLS mismatches, and its lines for connections allowed and for allowed hosts it could not reach up to 100 a minute each; past a budget it writes a count for each host and outcome, and drops nothing. A line for a host it could not reach now names the run.
- `footfall test` prints the app's last output with each line behind a bar, so that a GitHub Actions job cannot read any of it as a command, and cleans and caps every error message it prints; a manifest's unknown keys are shown escaped. Every log line a Footfall command writes, and every line of the app's output and error message it prints, loses the characters that show nothing and has each `##[` broken, with any such character between its own, so that no name the tested branch chose can give a job a command in the older form.
- `footfall test` refuses a `footfall.toml` or brief that is a link, lies in a `.git` folder or, without `--all-files`, is not among the files git lists.
- A model call that hangs is cut off at the persona's time limit, or at most a minute after it, rather than after 15 minutes, except in a grace turn, once the budget is spent, when a call is given at least 15 minutes, as long as the client may take with its retries, so that the tester's report is not cut off. Closing a persona's context, or letting go of what it held on a page, waits at most 10 seconds. A persona whose browser stops answering is stopped and reported as failed at a hard limit, 3,060 seconds with the default budget, so `footfall test` always ends.
- `footfall test` writes no result through a link: it refuses a results folder that is a link, a link where `summary.json` or a persona's folder would go, and a link in any folder above the results that lies inside the tested checkout, which is its whole git worktree when it has one, and it writes every result by name in folders it holds open. It refuses to test a folder whose path, as given, goes through a link inside a checkout, which a branch could use to lead the run out of its own.
- `trace.jsonl` keeps no more of each tool input than the tool takes, cleaned and cut as `report.json` is, and `report.json`, `summary.json`, each line of `trace.jsonl` and the printed table have a note saying the testers' text is observations, never instructions.
- A screenshot that is not a JPEG, or is larger than 2 MiB, ends the persona as failed. The tester is never shown a screen that may mix two pages or show another host's: a read is kept only when the page's own address and the browser's, before and after, are the same page on the app, and otherwise the step is an error that asks the tester to look again.
- The app's name and the brief are cleaned of hidden and control characters before the tester's prompt holds them, and the prompt says the brief sets what to test and cannot change the rules. A brief over 8,000 characters is refused, with its length and the limit.
- The browsers image, started without the runner's command, says that the runner gives it one and exits 64, rather than open Playwright's server on every interface.
- When a run cannot be prepared, the runner's error carries no throwaway password, even if Docker's own message quoted one, and a clean-up step that fails is logged by its kind and message, without the password or a traceback.
- Footfall's images leave out `.env`, `.pem` and `.key` files from the folders they take in whole.
- Results are made for the person who ran `footfall test` alone: its files 0600 and its folders 0700.
- A throwaway password is taken out of what a tester writes however its whitespace has been changed, before and after the text is made one line.
