# Changelog

All notable changes to Footfall are recorded here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). Footfall uses [semantic versioning](https://semver.org/).

## [Unreleased]

- The twelve starting personas are rewritten. Each id now says what the persona tests, such as `largest-text` or `right-to-left`. Each profile gives what the person needs and how they use the app. None gives an age, a job or a background. A manifest that names the old ids must use the new ones.
- `footfall test <folder>` runs the AI testers against a local folder. It copies only the files git tracks. A `.env` kept out of git never reaches a container whatever the tested branch's own `.gitignore` says. It refuses a sparse checkout or any checkout where git skips a file in the working tree. There a branch can track the name of a file of yours that git then leaves in place. Test a full checkout or pass `--all-files`. For the same reason it refuses a tracked file that your own git excludes name when the file is changed in the checkout, staged with content the last commit does not hold or marked assume-unchanged. Your excludes are `.git/info/exclude` and `core.excludesFile` or git's default global excludes. The first outranks the second as in git. The tree's `.gitignore` never counts. The refusal names the file, to be removed or renamed. For a file marked assume-unchanged it says so and says how to clear the mark if the file is the branch's own. Before the first commit every tracked file counts as staged. It matches those excludes with `core.ignoreCase` on whatever the repository says. An excluded name that differs from the tracked one by the case of an ASCII letter is caught on any volume. git folds no other case. Outside `--all-files` a tracked file that is changed, staged or marked assume-unchanged is also refused when the folder that holds it lists it under another name than the tracked one, by case or by the form of a letter. Your excludes make no difference to that. On a volume that folds those a file of yours would answer to the branch's name. A changed file with a decomposed name on a Mac is refused until it is renamed. So is a fresh checkout of a branch that tracks two names the volume holds as one, such as `README.md` and `readme.md`, on a volume that folds case. It is refused until the branch is fixed or the test is run from a volume that keeps them apart. A folder Footfall cannot list on the way to such a file is refused by name with the reason. `--untracked` adds the untracked files git does not ignore. That `.gitignore` decides which those are. It names each on standard error before the copy. A folder outside git needs `--all-files`, which warns that it copies everything. The two flags cannot be used together. It never reads or writes through a link. It never copies the repository's own git folder or a linked worktree's common folder however a crafted index or a `.git` file names them. It refuses a submodule because git does not list a submodule's files. With `--untracked` it refuses a nested repository too. It leaves out untracked files in any folder shaped like a git folder, such as a nested repository's. With `--all-files` it leaves out every `.git`, every folder git names as a git folder and every folder shaped like one. A folder is shaped like one when it has a `HEAD` file and an `objects` folder, or a `commondir` file. git runs with none of Footfall's environment, no input and no way to fetch. It reads a repository someone else owns only where the system trusts it. The footfall image trusts `/repo`, where the dev stack mounts the repository under test. `footfall test` asks the runner to prepare the app, start a copy for each persona and start the run's browsers. It signs each persona in when the brief asks. Then it writes each persona's report, step trace and screenshots, a summary of the run and a table of the results. The run is stopped however it ends. The throwaway password reaches only the seed step.
- A `footfall test` run has a cost ceiling the operator sets and the tested repository cannot raise. It is `--cost-ceiling` or `FOOTFALL_RUN_COST_CEILING_USD` in dollars. It is $12 unless set. That is the design's worst case for the default personas. Each persona checks the run's spend before each turn. Once the spend reaches the ceiling no persona starts another turn. A run can pass the ceiling by at most one turn for each persona running. A value that is not a number of dollars from 0.01 to 1000 is a setting error.
- A persona stopped at its hard limit reports what its model calls cost until then. `summary.json` no longer reads low when a run goes wrong.
- `footfall runner` serves the runner on a Unix socket that only its own group can use. The runner is the one process that holds the Docker socket.
- `footfall proxy` serves the egress proxy and its control socket.
- `FOOTFALL_DISK_BUDGET_MIB` sets how much disk the runner lets one run use, counting every copy of its app. It is 8192 MiB unless set. A value that is not a whole number from 1 to 16,777,216 (16 TiB) stops the runner with an error. So does an empty one.
- Each run's browser container puts a gate in front of Playwright's server. The server listens on loopback alone. The gate passes on only a WebSocket upgrade for a path made fresh for that run and told only to the orchestrator. It answers every other request with an empty 404. Code under test can neither learn the path nor launch a browser of its own there. Each connection has 10 seconds to send its request. Connections held open from one address cannot crowd out the orchestrator's. When the container stops the gate stops run-server and everything it started within a few seconds. If the gate goes, run-server goes with it.
- The browser image installs a Chromium managed policy that turns off Encrypted Client Hello because the egress proxy refuses it. The run's Chromium starts as the full build because the headless shell reads no policies.
- Every container the runner starts has an init process. The browser container has 512 MiB of shared memory for Chromium.
- The host has no address on a run's network and code under test cannot reach what the host serves. Every container the runner starts finds the egress proxy by name in its hosts file because Docker's name service does not answer under gVisor.
- `deploy/dev/compose.yaml` runs the proxy, the runner and an orchestrator for development. Each is read-only, runs under an init process and has no capabilities beyond what it needs. Only the runner mounts the Docker socket. Only the orchestrator receives the Anthropic key. The orchestrator mounts the repository under test read-only with its `.git` and the footfall image carries git. The copy is git's there too. `FOOTFALL_RUNTIME=runc` is for a machine without gVisor. With it every command warns that containers start without gVisor.
- The isolation workflow is `.github/workflows/isolation.yml`. It builds the images, installs gVisor and starts the dev stack. Then it runs the sandbox's own tests in its orchestrator. They cover what an app container can be, hold and reach, the egress proxy's decisions, the browser container's gate and a whole `footfall test` run of the demo app. It records the peak memory of each kind of container in the job summary.
- Tiny Tasks is the demo app in `demo-app/`. It is a to-do list with twelve planted usability and accessibility bugs, listed in its `BUGS.md`. It has a manifest and a brief for Footfall to test it.
- `footfall.toml` and the briefs are read strictly. Footfall reports all the problems it finds at once. A path on the app may not hold a control or invisible character, a `#`, or a `.` or `..` segment, however it is spelt. Each list holds at most 64 entries. A host listed twice is a problem. A byte order mark at the start of a file is ignored.
- The egress proxy refuses the deprecated 6to4 relay anycast range 192.88.99.0/24, the Port Control Protocol anycast addresses 192.0.0.9 and 2001:1::1, the TURN anycast addresses 192.0.0.10 and 2001:1::2, and ORCHIDv2's 2001:20::/28, which no public host uses. A host name whose last label is a number in any base is taken for an address and refused.
- A persona's `locale` must be a language tag such as `en-GB`. Its `timezone` must be one the system's time zone database knows. A typo stops the personas file from loading.
- Every container the runner starts has a private IPC namespace and a core file limit of 0. Its settings say that `/tmp` runs no programs, which Docker already ensured. The runner walks an app's files without ever opening a folder through a link. It stops a run whose files keep vanishing or changing under three disk measures in a row and says to keep scratch files in `/tmp`. Each measure is taken twice when the first skips something. The runner remembers the latest 10,000 run ids it has stopped.
- Text a tester writes loses the characters that show nothing, such as zero-width spaces, word joiners and the byte order mark. It loses the bidirectional controls too. The line and paragraph separators become plain new lines.
- `footfall test` refuses a file that is a hard link under another name to the repository's git configuration or to any other file of its git folder, such as a submodule's configuration. For a submodule that covers each superproject's git folder out to the outermost. It refuses such a file if it cannot read or find all of them. It warns once for each folder it leaves out because it is shaped like a git folder. That includes one whose `HEAD` is a link.
- In a GitHub Actions job Footfall registers each secret it makes with `::add-mask::` and the job's log shows `***` in its place. The secrets are a run's throwaway password and the path of its browser server. The command goes only to a pipe or a terminal. It never goes to a file an artefact could hold or to /dev/null. If no stream a job reads takes it, the run stops before the secret is used.
- The isolation workflow's `memory.json` says whether a kernel peak covers the run or the stack's whole life. It says so for the total too.
- The runner keeps each run's files in `/var/lib/footfall-runs` (`FOOTFALL_RUNS`). The folder must belong to root and be writable by root alone or the runner will not start. The runner checks the folders above it as its own container shows them. On the host each folder above it must be root's alone too, as on a stock Ubuntu. Only the runner mounts it and the orchestrator no longer can. Make it with `sudo install -d -o root -g root -m 0700 /var/lib/footfall-runs`. The runner writes, gives away, sets the modes of and removes everything there through folders it holds open and never through a link. It opens a folder's path again before it names it to Docker.
- A run's folder is removed by a walk that holds a few open folders at a time however deep the tree its code made. It no longer holds one for each level.
- Before it serves the runner removes every container, network and run folder that an earlier runner left and says what it removed. It stops any run that lasts longer than `FOOTFALL_RUN_LIFETIME_MINUTES`, which is 90 unless set. The runner refuses to start if the setting is not a whole number from 1 to 10080. A hang-up stops `footfall test` and its run as SIGTERM does.
- The egress proxy listens only at its own address on each run's network and no longer on every interface. It listens from when the runner tells it until the run stops. Its control socket answers root alone and checks the connecting process's user id.
- The proxy looks up each run's names on that run's own threads. At most 8 lookups are in flight for each client and 16 for each run. One run's slow name server cannot delay another's. Past those limits the proxy answers 503. Those threads go once the run holds neither an allow list nor a listener. A run it no longer serves gets none. Before it serves, the runner revokes in the proxy every run that nothing else shows is still there.
- The proxy refuses the AS112 and AMT anycast ranges. For plain HTTP it drops `Forwarded`, `X-Forwarded-Host` and the other headers that name another host, and it refuses header values holding the bytes 0x80 to 0x9F. Revoking an allow list closes that address's open connections.
- The proxy writes each client's refusals for a run in full up to a budget a minute. The budget is 20 for routine refusals, which are its connection and lookup limits and hosts off the list. All others, such as TLS mismatches, have a separate 100. Its lines for connections allowed and for allowed hosts it could not reach are written up to 100 a minute each. Past a budget it writes a count for each host and outcome and drops nothing. A line for a host it could not reach now names the run.
- `footfall test` prints the app's last output with each line behind a bar so that a GitHub Actions job cannot read any of it as a command. It cleans and caps every error message it prints. A manifest's unknown keys are shown escaped. Every log line a Footfall command writes loses the characters that show nothing and has each `##[` broken, with any such character between its own. So does every line of the app's output and error message it prints. No name the tested branch chose can give a job a command in the older form.
- `footfall test` refuses a `footfall.toml` or brief that is a link or lies in a `.git` folder. Without `--all-files` it also refuses one that is not among the files git lists.
- A model call that hangs is cut off at the persona's time limit or at most a minute after it. It used to be cut off after 15 minutes. The exception is a grace turn once the budget is spent. There a call is given at least 15 minutes so that the tester's report is not cut short. That is as long as the client may take with its retries. Closing a persona's context waits at most 10 seconds. So does letting go of what it held on a page. A persona whose browser stops answering is stopped and reported as failed at a hard limit. The limit is 3,060 seconds with the default budget. `footfall test` always ends.
- `footfall test` writes no result through a link. It refuses a results folder that is a link. It refuses a link where `summary.json` or a persona's folder would go. It refuses a link in any folder above the results that lies inside the tested checkout. The checkout is its whole git worktree when it has one. It writes every result by name in folders it holds open. It refuses to test a folder whose path, as given, goes through a link inside a checkout. A branch could use such a link to lead the run out of its own checkout. A link of your own above every checkout is followed. So is one that leads to a checkout or into it. The branch's links below where it leads are refused all the same.
- `trace.jsonl` keeps no more of each tool input than the tool takes, cleaned and cut as `report.json` is. `report.json`, `summary.json`, each line of `trace.jsonl` and the printed table have a note saying the testers' text is observations, never instructions.
- A screenshot that is not a JPEG or is larger than 2 MiB ends the persona as failed. The tester is never shown a screen that may mix two pages or show another host's. A read is kept only when the page's own address and the browser's are the same page on the app before and after. Otherwise the step is an error that asks the tester to look again.
- The app's name and the brief are cleaned of hidden and control characters before the tester's prompt holds them. The prompt says the brief sets what to test and cannot change the rules. A brief over 8,000 characters is refused with its length and the limit.
- The browsers image exits 64 when started without the runner's command and says that the runner gives it one. It does not open Playwright's server on every interface.
- When a run cannot be prepared the runner's error carries no throwaway password even if Docker's own message quoted one. A clean-up step that fails is logged by its kind and message without the password or a traceback.
- Footfall's images leave out `.env`, `.pem` and `.key` files from the folders they take in whole.
- Results are made for the person who ran `footfall test` alone. Its files are 0600 and its folders 0700.
- A throwaway password is taken out of what a tester writes however its whitespace has been changed. That is done before and after the text is made one line.
